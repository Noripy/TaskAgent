# ペルソナと設計原則

## ペルソナ

- 20 代・社会人 1〜3 年目
- タスクを小さく分解できず、着手前に止まる
- 完璧主義で「ちゃんとまとめてから報告しよう」として報告が遅れる
- 過集中・過思考で、人から言われたことを取りこぼす。あとで「言ったよね？」と言われる
- 報連相の文面を書くのに時間がかかる

## 設計原則（迷ったらここに戻る）

1. **捨てない**: 入力は整える前に保存する（`captures.raw_text`）。整形は後から AI がやる。
2. **聞きすぎない**: 質問は 1 回 2 個・合計 3 回まで。それ以上は仮置きで進める（`MAX_CLARIFICATION_ROUNDS`）。
3. **最初の一歩を 15 分にする**: 行動は 15 分以内に着手できる粒度に分解（`MAX_ACTION_MINUTES`）。
4. **70 点で出す**: 報連相の下書きは 3 行以内。コピーしてそのまま送れる。
5. **本人の行動を褒める**: 振り返りの「良かったこと」は結果ではなく行動を主語にする。
6. **設定を減らす**: ログイン = GitHub 1 回。保存先の設定は 1 画面。

## 報連相の型（プロンプトが従う定義）

| 種別 | いつ | 下書きの骨子 |
|---|---|---|
| 報告 | 指示されたことの結果・進捗 | 結論 → 事実 → 次にやること |
| 連絡 | 相手が知っておくべき事実 | 事実 → 影響 → 期限 |
| 相談 | 判断に迷っている | 状況 → 自分の案 → 聞きたいこと |
