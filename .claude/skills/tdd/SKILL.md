# TDD で進める

引数: 変更内容の一言説明（例: `/tdd メモに「気分」フィールドを追加`）

## Plan（コードを書く前。飛ばさない）

`/plan` の型で、**なぜ必要か・影響範囲・最小案と代替案 2 つ以上・テスト方針・確認方法**を提示する。
すでに `/plan` を通していればその内容をここに置くだけでよい。
危険・不可逆・スコープが変わる判断があるときだけ承認を待ち、それ以外は Red へ進む。

## Red → Green

1. **どの層か決める**。純粋ロジックなら `src/core`、I/O が絡むなら `src/server`。迷ったら core に寄せる。
2. **Red**: 失敗するテストを 1 つだけ書く。
   - core: `test/core/*.test.ts`
   - server 単体: `test/unit/*.test.ts`（fetch モック）
   - server 結合: `test/workers/*.test.ts`（`setupApi()` と `apiClient` を使う）
   - メモやインサイトの見本は `test/fixtures/memo.ts` から取る（自前の literal を新しく作らない）
   - 実行して **必ず失敗を確認**する: `pnpm test:unit`（結合は `pnpm test:workers`）
3. **Green**: テストが通る最小の実装を書く。設計を良くしようとしない。
   - **KISS**: 仕組みを増やさない。分岐・抽象・設定より、素直な実装を選ぶ。
   - **PIE**: 名前で意図を語る。定数はマジックナンバーにせず名前を付ける（`MAX_ACTION_MINUTES` など）。
     名前で表せない「なぜ」だけをコメントに書く。
   - 原則の意味と実例は `docs/notes/design-principles.md`。
4. 2〜3 を、要求を満たすまで小さく繰り返す。

## Refactor（All Green になったら必ず通る。飛ばさない）

テストが全部緑になった状態が唯一の安全網。緑のまま、**振る舞いを変えずに**次を順に当てる。

1. **YAGNI — 使われていないものを消す**
   - `grep -rn "<名前>" src test | wc -l` が 1（定義だけ）なら消す。
   - 本番から呼ばれないエンドポイント・repo メソッド・export を残さない。「いつか使う」は理由にならない。
   - テストだけが生かしているコードは、コードとテストの両方を消す。
2. **DRY — 同じ知識が 2 箇所以上にないか**
   - 3 回目に現れたら抽象化する（2 回目までは我慢する＝早すぎる抽象化を避ける）。
   - テストの重複（セットアップ・fixture・リクエスト定型）はヘルパーに寄せる。スキーマ変更で複数テストを直したなら、それは DRY 違反のサイン。
3. **関心の分離・カプセル化**
   - ルートは薄く。ロジックは `services/` `jobs/`、SQL は `db/repo.ts`。
   - 自前の型でフレームワークの型を再実装しない（例: Hono は `Context<AppEnv>` を使う）。
   - 分岐（環境による切り替えなど）は 1 箇所のファクトリに閉じ込める。
4. **SLAP — 1 つの関数の中で抽象度を揃える**
   - 「メモを読む」と「base64 に変換する」が同じ関数に並んでいたら、細部を `lib/` に降ろす。
   - 関数の中身を上から読んで、粒度が揃っているかで判断する。
5. **OCP — 次に同じ種類のものを足すとき、何ファイル触るか**
   - 同じ変更のたびに複数ファイルを直しているなら、そこが閉じていない箇所。
   - ただし **2 回目までは我慢する**。最初から拡張点を作り込むのは KISS 違反。
6. **命名と一貫性**
   - 同じ役割のファイルは同じ形にする（ルートはすべてメソッドチェーン、など）。
7. **確認**: `pnpm verify`（Docker なら `pnpm docker:verify`）。**テストは 1 つも変えずに緑のまま**であること。
   - 振る舞いを変えたくなったら、それは Refactor ではない。Red から別サイクルでやる。
8. 消した量・減った重複を PR 本文に 1 行で書く（レビュアーが差分を読む助けになる）。

## 禁止

- 計画（なぜ・案の比較）を出さずに実装を始める
- テストを後回しにして実装から書く
- 1 サイクルで複数の振る舞いを追加する
- 通らないテストを skip する
- All Green を確認したら Refactor せずに終える
